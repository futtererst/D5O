# Phase 2G Work UI acceptance

The actual application was started against a disposable loopback Supabase instance by `node scripts/p0a/run-phase2g-tenant-neutral-work.mjs`. Separate authenticated tenant administrators selected their organizations, opened the tenant-neutral Work route, inspected their connected Work and six-phase status, reloaded it, created another connected Work through the browser form, opened its Discover status, and received HTTP 403 for foreign-tenant GET and POST requests. Desktop and mobile screenshots are in `evidence/phase2g-browser/` (especially `a-work-operate.png`, `b-work-operate.png`, `a-browser-created-work.png`, `b-browser-created-work.png`, and the matching mobile images). The run stopped the web server and removed its disposable database.

The page shows Work identity, owner, configuration pin, current phase, completion basis, early Develop preparation, support status, financial status and projection replay state. The responsive layout has links to existing connected Work creation and configuration. Operate handoff and activation controls appear only to an authorized Operations role at the relevant state; authoritative RPCs still decide whether a command succeeds.

**Not accepted:** Browser controls have not performed Discover through Operate end to end. The test harness performed canonical transitions through authenticated RPCs, then the browser inspected the result. The browser did create fresh Work and show its Discover state. Missing forms include Define decisions, Design package and evidence review, workforce commitment, field evidence and independent customer acceptance, support-document review. Thus the two mandated UI journeys are blocked. Browser screenshots are actual pages, but they are not proof of UI-driven transition completion.
