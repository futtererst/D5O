# Phase 2H security results

The new API action set is bounded to Define review and handoff actions. The route resolves the signed-in tenant context through `customerWorkScope`, rejects pilot keys, checks Work identity in the selected tenant, supplies tenant and command identity server-side, and calls the existing session-scoped RPC. The RPC enforces current revision, distinct submitter/reviewer/receiver, membership, role, pinned configuration and tenant ownership. A browser-only role check is not the security boundary.

The focused task-projection test passed eight assertions: submitter exclusion, commercial and delivery role separation, field-role exclusion, opposing-reviewer exclusion, handoff sender exclusion, correct receiver visibility, and completed-task removal. In the strengthened two-tenant browser run, an authenticated finance actor's cross-tenant Define POST returned 403 and a delivery-review POST returned 403 with `define_review_role_denied`. These requests used `fetch` from the signed-in page, so the origin check was satisfied; `invalid_origin` was explicitly excluded. The state remained eligible for the following valid browser decision. The inherited Phase 2G fixture also checks cross-tenant read/write denials, but its older Playwright API POST lacks browser origin headers and is not credited as a command-level denial. Revoked-user, suspended-tenant, forged-ID, stale and concurrent HTTP tests for the new Define adapter remain unexecuted.
