# Phase 2A two-tenant qualification

Source baseline: `448c00be9d09e4b527aa7f3a3c89d99ce5ceda6f`. Migration: `20261023123751_d5o_phase2a_organization_people.sql`. The [machine-readable run](evidence/phase2a-two-tenant-results.json) creates separate fictional Auth users for Rybex Test and Independent Enterprise Test in one disposable loopback Supabase stack. It uses the same RPC and Next.js code for both and removes the stack afterward. Synthetic invitations use already confirmed local users; no real email is sent.

The final run passed **11/11 checks with no setup error and verified cleanup**. It covered two units and two locations in each tenant, three A teams and two B teams; independent profile edits; cross-tenant manager, unit, record and workforce denial; stable ID after rename; hierarchy cycle, duplicate code, stale revision and in-use retirement; multiple team memberships; role change, self-promotion denial, immediate suspension, reactivation and removal; exact-payload idempotency; tenant-bound invitation acceptance and replay; revoked/expired denial; concurrent command replay and audit. Authenticated A/B administrators created additional units through the UI and were denied forged other-tenant API reads. The browser also visited every new administration section, created an invitation, and accepted it as the signed-in recipient.
