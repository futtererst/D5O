# Hosted configuration runtime contract

1. Resolve the authenticated Supabase user and active workspace membership for every command. A workspace key supplied by the browser is only a selector; the database independently checks membership, tenant, work and version ownership.
2. New Work receives the one active hosted published version. Historical Work retains its `configuration_version_id`; a later activation never rewrites that pin.
3. The `serviceWorkApproval` manifest object has `schemaVersion: 1`, integer `thresholdMinor`, `currency: USD`, `comparison: greater_than`, `authorityRole: admin | operations_leader` and `unavailableBehavior: block`. The editor and database validator accept only a bounded nonnegative integer threshold. The rule is `amountMinor > thresholdMinor`; equality does not require additional approval. No currency conversion occurs.
4. Draft edits require expected active ID and edit revision. Validation checks policy shape and an active authority-role member. The existing command writes reason, actor, membership, before/after, receipt and version status. Activation supersedes the old version and makes the candidate the default. A stale draft fails. Safe rollback requires a new draft and audited activation; published history is retained.
5. `d5o_hosted_service_approval_command_v1` reads only the Work Record's pinned published or superseded version. It rejects missing policy, foreign work, missing membership, wrong currency, inappropriate work type, duplicate request and changed amount. It snapshots threshold and policy version in `service_approval_requests`, appends a decision event and stores an idempotent receipt. An independent member of the configured role must decide a pending request.
6. Direct authenticated table privileges are revoked and RLS is enabled on the approval request, event and receipt tables. Only the bounded security-definer RPC is granted to `authenticated`; it checks `auth.uid()` and current membership before reading or writing.

The global/environment/plan hierarchy is limited to fixed code and deployment guards plus a tenant version in this slice. No speculative plan override or second policy engine was added. The older `config_*` and prototype pricing writers remain for historical behavior until parity and replacement commands are qualified.
