# Phase 2H-U Deploy action map

Baseline: `639308061ff236ac0afb6487088a44c315e9b554`. This matrix covers the eight inherited Deploy inventory rows (`deploy-36` through `deploy-43`) and the intermediate reviews required to complete them. The existing 54-row inventory, including two duplicate Design entries, remains the denominator. Hosted commands and their transaction receipts are the business authority; My Work is a projection.

| Action and inventory | Actor and task | Exact basis | Command and input | Completion and next responsibility |
| --- | --- | --- | --- | --- |
| Start field work (`deploy-36`) | Assigned field worker sees an authorized assignment; Operations authorizes the start | Parent Work, accepted Design release, published booking, crew binding and field-start permit | Existing `d5o_hosted_field_start_command_v1` with source, Design, schedule and Deploy revisions and command ID | Authorized permit; worker may record factual progress. A connected-service child job is separately authorized and does not substitute for this parent permit. |
| Capture execution fact (`deploy-37`) | Assigned worker, My assigned Work | Exact Work, package, release and booking; pinned policy and current permit | `d5o_hosted_field_fact_command_v1`: `save-report`, then `submit-report`; measured quantity/unit, hours, summary, linked evidence, revision and command ID | Draft then Submitted report; independent report review task. |
| Record inspection (`deploy-38`) | Assigned worker after reviewed report | Release requirement ID, report, package and booking | `d5o_hosted_field_fact_command_v1`: `record-inspection`, result, method, evidence and optional failed-result reference | Submitted inspection; independent quality verification task. |
| Retain completion evidence (`deploy-39`) | Assigned worker | Exact Work, package, release and booking; private Storage path | Upload to existing `d5o-deploy-evidence` bucket, then `d5o_hosted_field_evidence_command_v1`: `register-upload`, checksum, file metadata, revision and command ID | Uploaded evidence; independent evidence review task. Upload alone grants no acceptance. |
| Review completion evidence (`deploy-40`) | Independent field supervisor or Operations leader | Uploaded evidence object, exact release and Storage object | `d5o_hosted_field_evidence_command_v1`: `review-evidence`, decision and reason | Reviewed or Returned evidence; a Reviewed decision can satisfy the pinned additional policy. |
| Record issue or exception (`deploy-41`) | Assigned worker; subsequent roles depend on disposition | Exact parent Work, accepted package release, optional report and evidence | Existing `d5o_hosted_field_change_command_v1`: `raise`, with title, impact, evidence, revisions and command ID | Open change holds further start/completion; independent assessment and controlled resolution. This is the authoritative issue domain for connected Work. |
| Submit completion (`deploy-42`) | Worker submits report; Operations leader makes independent package completion decision | Reviewed measured report, verified inspections, resolved blockers and pinned Deploy policy | `d5o_hosted_field_fact_command_v1`: `review-report`, `review-inspection`, `review-completion` as separate decisions | Reviewed completion; package turnover preparation. A worker submission is not itself a completion approval. |
| Record customer acceptance (`deploy-43`) | Project manager prepares customer evidence; independent authorized recipient decides | Exact turnover and whole-Work scope, signed PDF through existing customer decision evidence service | `d5o_hosted_acceptance_command_v1`: `assemble-turnover`, `accept-client`, `respond-operate`, `accept-work`, `respond-operate-work` | Accepted package and whole Work; Deploy phase completes and Operate handoff becomes available. Financial closeout stays separate. |

Every command uses authenticated actor, active membership, active tenant, tenant-owned Work, expected source/decision revisions, a command ID, and hosted audit/receipt records. Private evidence reads require the same scope. Worker routes expose only the assigned package projection; management review routes must not grant a field worker tenant-wide Work visibility. The current pilot worker route is hardcoded to Rybex, so Phase 2H-U adds a tenant-neutral adapter while retaining that pilot route.
