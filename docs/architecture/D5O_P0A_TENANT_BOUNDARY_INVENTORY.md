## Boundary decisions

The hosted API accepts a client workspace key in several routes, but the tested `work` and `admin-configuration` routes independently resolve active membership server-side. No tested route was shown to grant a client-provided workspace as authority. The rest of the generated inventory must be traced to RPC/DB checks before that statement can be generalized. Service-role operations and SECURITY DEFINER functions are the highest-value manual review targets; the raw count of SQL declarations is not a count of live endpoints.

Current fixed `rybex`/`rotork` allowlists (`membership-access`, `handoff-routes`, evidence, search) and Rybex-only admin configuration are pilot controls [C]. The B API denial is intentional and was preserved [T]. They must remain until a separately qualified tenant eligibility and administration replacement exists. No production tenant record was created.

## Coverage gap by requested domain

The executable suite covers representative hosted work, configuration, actor/membership, direct DB grants, HTTP GET, storage direct access, replay and conflict. It does **not** yet qualify every opportunity, project, work package, workforce, schedule, finance, business event, audit, export, cache key, signed-URL business route, server action, service-role writer or background retry. These are explicitly **partial/blocked**, not implied passes. Gate B remains **FAIL** because the candidate inventory is broad but has not been manually mapped and negatively tested for every security-critical privileged path.
