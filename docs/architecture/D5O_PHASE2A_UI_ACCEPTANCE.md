# Phase 2A administration UI acceptance

The existing `/work/admin` shell now contains Organization, Settings, Business units, Locations, Teams, People, Invitations, Roles & access and Administration activity. It keeps active workspace context in navigation and uses the existing admin identity boundary. Lists have search and 25-row paging, status labels, empty/loading/error messages and responsive overflow tables. Edit forms require a reason. Retirement, access changes and team-assignment ending require confirmation. The user-facing controls call `/api/d5o-hosted/org-admin`; that route forwards to authenticated tenant-scoped RPCs and never mutates private tables directly.

The People view distinguishes membership role/status from a linked workforce profile. Team assignments and primary workforce unit/location use authoritative profile and assignment IDs while displaying readable names. The invitation page is accessible to the signed-in recipient even before tenant membership; acceptance is authorized by the invitation command rather than the admin navigation.

Browser qualification signed in as both tenant administrators, visited every new administration section, used visible controls to create business units and an invitation, accepted that invitation as its signed-in recipient, verified results through the database commands, denied forged other-tenant API reads, and retained actual desktop/mobile screenshots. The result is [`phase2a-two-tenant-results.json`](evidence/phase2a-two-tenant-results.json); screenshots are under `docs/architecture/evidence/phase2a-admin-ui/`. The local preview was ephemeral and stopped with fixture cleanup.
