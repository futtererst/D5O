# Phase 1B connected service command paths

Source baseline: `7b8a629d57f4652acd7545ac244555e228a563d4`. The inventory is limited to reachable connected service authorization and job boundaries. The database functions are the final authority; route checks alone are insufficient.

| Path | Entry and actor | Tenant, Work, version | Pre-1B behavior | Correction and regression |
| --- | --- | --- | --- | --- |
| Customer service authorization | `POST /api/d5o-hosted/prototype-operate-command?action=record-service-authorization` → `d5o_hosted_service_pricing_command_v1`; active Operations leader | Route selects hosted workspace and presentation ID; RPC verifies membership, canonical parent and Operate revision; parent has immutable hosted version pin | Exact reviewed estimate and external customer evidence were required, but tenant threshold approval was never read | RPC wrapper locks the workspace and requires the existing hosted approval ledger decision for the exact connected request before invoking the prior command. Direct RPC and route share this boundary. Regression: missing/stale/revoked decision, cross-tenant denial, valid decision. |
| Executable service job | Same route, `action=create-job` → `d5o_hosted_service_job_command_v1`; active Project manager or Operations leader | RPC verifies membership, canonical parent, current request, Work/catalog/Operate revisions and child work type right; child inherits parent version | Partial customer authorization was checked but the independent tenant threshold approval was not | RPC wrapper requires the exact approval in the same transaction before the prior job command. Prior command keeps its duplicate visit, receipt and revision controls. Regression: pending A denial, B no extra approval, valid A job, replay and conflict. |
| Older related-work creation | Same route's service-role fallback → `d5o_hosted_create_related_work_v1`; server-supplied active member | RPC checks workspace, member, parent and version, then creates a child | The generic `create-job` variant could have avoided a policy check | Service-role wrapper guards `create-job` against the same ledger and revokes direct execute on the renamed prior function. `generate-maintenance` and `open-lifecycle` retain their separate paths. Regression: direct service-role stale-decision denial and prior-function privilege check. |
| Threshold request and decision | `POST /api/d5o-hosted/service-approval` with connected request → `d5o_hosted_connected_service_approval_command_v1`; member requests; independent configured Operations leader or admin decides | Membership, canonical parent, connected request, approved estimate and immutable parent version | Phase 1's Work-level command had no connected request/estimate identity | Adapter writes to the **same** hosted approval request/event/receipt tables with request ID, cycle, scope fingerprint, estimate revision, amount and currency. The Work-level command remains for its historical scope. Regression: A/B, wrong actor, replay, stale scope, audit. |
| Approval visibility | `GET /api/d5o-hosted/service-approval` → `d5o_hosted_connected_service_approval_read_v1`; active tenant member | Server resolves the member, parent and current request | No connected policy status was exposed to the Operate panel | Returns policy version, threshold, decision status and permission flags. UI uses these for request/decision actions and disables customer authorization while blocked. Database commands still enforce independently. |
| Downstream service basis and execution | `d5o_hosted_service_basis_command_v1`, design/deploy service commands; active role under existing phase contracts | Child service Work and `current_service_source_v1` resolve the parent request and inherited pin | These commands assume a job already exists and apply their own service source, design and deploy controls | No extra writer was added. Protected job creation now requires approval; source checks still reject mismatched estimate/customer authorization. Existing jobs are not repinned or rewritten. A full six-phase pilot journey remains a separate regression gate. |

`d5o_hosted_prototype_save_v1` and `d5o_hosted_command_save_v1` cannot import protected connected decisions into a Work snapshot; their existing guards remain. `d5o_hosted_create_connected_work_v1` creates a parent Work Record, not an executable service job. Browser-only prototype actions without a canonical hosted Work Record are historical preview paths; they cannot produce an authoritative connected job. The service-role related-work route is production-reachable while its fallback remains present, so it is guarded rather than dismissed as a prototype.
