# Phase 2D hosted configuration contract

The authoritative record remains `d5o_hosted.configuration_versions.manifest_json`. Phase 2D adds optional `phase2dRequirements` with exactly `schemaVersion: 1`, `defineRiskNarrative: boolean`, and `developOptionEvidence: boolean`. Omission from older published versions means both additions are optional. The two fields apply to all Work Types in the tenant version. Per-Work-Type Design, Deploy and Operate booleans stay in the existing `d5oPresentation.phaseContract.workTypes` structure: `designControls.requireMop`, `deployControls.requireReviewedEvidence`, and `operateControls.requireDocumentationReview`.

The hosted configuration admin RPC remains the sole writer. It accepts draft-only `save-policy` for the two new keys and the three named existing controls, requires current active version and expected edit revision, rejects malformed booleans, and records reason, actor, receipt, and event. Publication checks the complete `phase2dRequirements` shape. Validation freezes the candidate; activation supersedes the prior active version. Published and superseded records are never edited.

New Work pins the active version and digest. The Define and Develop command wrappers resolve the Work record, active membership, tenant-owned version, matching digest, and source identity before evaluating the policy. Older Work continues to use its own published or superseded version. The pre-existing Design, Deploy, and Operate commands read their relevant Work-Type control from the same pin.

Tenant settings add bounded requirements. They cannot change workspace membership, platform role authority, evidence custody, customer acceptance, mandatory engineering/safety review, financial approval, or Rybex/Rotork pilot routing. The optional reviewed-evidence setting controls an additional completion-review check; it does not remove the mandatory provenance and acceptance checks elsewhere.

The inherited `prototype-v2` phase contract's stored sequence is Discover, Define, Develop, Design, Deploy, Operate. This differs from the requested product sequence, which places Design before Develop. Phase 2D does not mutate historical contracts or rewire the connected workflow. The mismatch is recorded as a release issue and must be resolved with a compatible transition plan before full six-phase claims.

Schema migration order: `20261023153646_d5o_phase2d_phase_policies.sql`, then `20261023153752_d5o_phase2d_define_develop_guards.sql`. These are local files only. A staging rehearsal must validate existing published manifest compatibility, permission grants, Work pins, replay receipts, and forward recovery before any hosted application. Reverse schema rollback after publication would risk losing a customer's chosen policy; restore from a pre-migration snapshot only under an approved change plan.
