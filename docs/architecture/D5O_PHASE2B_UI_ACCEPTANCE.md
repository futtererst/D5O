# Phase 2B administration UI acceptance

The vendor-only `/platform-admin` page now contains a searchable/filterable tenant directory, a guided customer form with explicit review, and a governed template directory. `/platform-admin/tenants/[workspace]` shows customer profile, lineage, invitation status, readiness, audit activity and the applicable vendor actions. Recovery and activation require a reason and confirmation. No impersonation or raw database action is exposed.

The recipient uses `/work/initial-invitation` to accept a tenant-bound offer. `/work/onboarding?workspace=...` shows required, recommended and optional setup from the server. Links reuse Phase 2A organization and Phase 1 Configuration Center pages. Readiness confirmation is enabled only when the authoritative read says required checks pass. The server still rechecks every transition. Existing `/auth/set-password` routes newly invited administrators into initial-offer acceptance.

All forms have labels, visible state, and live error/status text. The vendor directory and forms remain usable at narrow widths via the existing administration CSS layout and scrolling tables. Actions call the provision/onboarding API routes, which forward to authoritative RPCs. The authenticated browser test creates a customer through the review form, accepts its initial-admin invitation, publishes its required policy, submits readiness, and activates it from the vendor detail page. It also confirms a customer administrator receives HTTP 403 from the vendor API.
