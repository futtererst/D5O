# Phase 2F Operate acceptance

The prior Operate command treated a text description as satisfying `requireDocumentationReview`; it did not require a reviewed document. Migration `20261023180000_d5o_phase2f_operate_review_guard.sql` wraps the existing authoritative writer for `accept-support`. For a pinned policy that requires review, the wrapper locks the Work, Deploy and Operate rows, verifies the expected revisions, and requires an independently **Reviewed** `as-built` obligation for every accepted turnover. The obligation must match `support_document_basis_v1`, which binds evidence to the exact turnover, accepted release, package and whole-Work acceptance. The existing Operate command performs the mutation, receipt and audit write in the same transaction. Replays with an existing command receipt delegate to its idempotency logic. The prior writer is moved to the private `d5o_hosted` schema with direct execution revoked.

Historical published versions without the later optional `requireDocumentationReview` field retain the earlier contract. A missing work-type policy remains an error. The wrapper adds a requirement only when the pinned version explicitly enables it. It does not alter previously accepted support, closeout or finance history.

The fixture attempts premature acceptance, then receives the accepted Deploy handoff, identifies an asset, attempts support acceptance without review, uploads and registers the exact support document, submits and independently reviews it, accepts support, and activates. Tenant B's optional policy must not fabricate a review. The existing financial state stays pending; Phase 2F does not claim billing or financial closeout qualification. The machine-readable test result is authoritative for which steps actually passed.

Rollback in an approved staging rehearsal would restore the previous public Operate function and its grants from the migration backup, after checking no new support acceptance depends on the review guard. Forward recovery is preferred if the new policy is in use. No hosted or production migration is authorized by this package.
