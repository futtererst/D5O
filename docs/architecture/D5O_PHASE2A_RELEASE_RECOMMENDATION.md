## Priority decision

| Candidate | Sequencing decision |
| --- | --- |
| Controlled provisioning, initial administrator and configuration template | Next: one governed flow replaces manual SQL setup for a customer. |
| Branding/preferences, role customization, lifecycle controls, platform support, plans/entitlements and integration administration | Later: each can consume the tenant created by that flow; none should be a prerequisite for a first repeatable tenant. |

Expected business value: a vendor can create a customer using one application and a reusable policy template, and the customer can then administer its organization without developer intervention. Dependencies: qualified Phase 2A membership/invitation commands, approved template from Phase 1, and a staged migration/rollback path. Principal risks: accidental privilege transfer to the initial administrator, duplicate or partial tenant creation, template drift, and weakening of pilot gates. Relative effort: **medium to large** (one bounded vendor workflow plus disposable qualification).

Acceptance: vendor-only create/activate commands are idempotent and audited; customer administrators cannot invoke them; tenant status and initial administrator are consistent; configuration template is copied as a tenant-owned version; two new fictional tenants provision through the same command without manual SQL; revoked/expired onboarding invitations fail; cross-tenant access fails; cleanup and inherited regressions are recorded; no production change occurs.
