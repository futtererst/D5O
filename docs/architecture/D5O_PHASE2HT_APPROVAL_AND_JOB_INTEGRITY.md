# Phase 2H-T approval and job integrity

Phase 1B remains the authoritative service approval system. `d5o_hosted_connected_service_approval_read_v1` resolves the pinned tenant policy and the current estimate, currency, request cycle, and scope fingerprint. `d5o_hosted_connected_service_approval_command_v1` persists an independent, request-bound decision. `d5o_hosted_service_pricing_command_v1` requires the applicable decision when recording service authorization. `d5o_hosted_service_job_command_v1` checks authorization and approval again in the job transaction. The browser cannot replace these checks.

The Phase 2H-T approval gate exercised amount and material scope changes, historical decision retention, stale authorization and job denials, new decision approval, a separate request denial, the USD 25,000 no-extra-approval case, concurrent job creation, changed authority and revoked approver. The disposable result is `evidence/phase2ht-approval-gate-results.json`: 14 passed, zero failed, cleanup verified. The fixture changes scope in disposable state to model an adversarial material change; it does not establish a customer-facing scope editing journey.

The tenant-neutral server routes now use `customerWorkScope` before invoking the same Phase 1B commands. The legacy Rybex/Rotork context remains unchanged. The customer authorization evidence route has the same tenant-neutral scope check and still binds custody to the exact Work/request. These new adapter paths have not passed the complete Gate B browser and cross-tenant matrix; Phase 1B RPC success alone does not qualify them. Job creation is not treated as a second approval engine.
