**Release disposition: held.** Deploying the database-backed branch before the schema is reconciled risks a build serving commands that the live database cannot execute. Merging the draft PR could also trigger deployment through a connected Git workflow, so the PR remains draft and `main` is unchanged. No live migration, production alias update or production-data mutation was attempted.

To resume this exact release, identify and reconcile every live migration version with the checked-in sequence; take a verified recoverable backup; rehearse the forward migration on a representative isolated copy including Auth/membership and storage metadata; verify the application against that resulting schema with role-separated users; define rollback/forward-repair for the database and hosting alias; then recheck the exact PR head and production configuration before merging or promoting. The existing empty-database replay is useful but does not replace populated cutover evidence. Creating a paid hosted branch is not assumed or authorized by this record.
