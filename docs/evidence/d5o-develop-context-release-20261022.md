## Reproduction and correction

Read-only navigation on the previous isolated production build reproduced a specific failure: `/work?workspace=rybex&view=develop&developPanel=task&record=<fictional-id>` displayed the ordinary commercial workspace and rewrote the URL to `developPanel=workspace`. Source inspection found that the legacy My Work pricing/proposal callbacks set `discoverEntry` but `go()` cleared `taskFocus`; serialization could then erase `focus`, and restoration treated the remaining record as a workspace. Hosted My Work uses separately built exact task links, so this legacy callback failure is **not** claimed as a reproduced hosted failure.

The new shared Develop route parser/builder distinguishes pipeline, exact workspace, exact task (record, recognized focus, source revision), and invalid task. Legacy pricing/proposal callbacks now provide exact focus and revision through `go()`. An explicit pipeline ignores stale record/task parameters. Missing or malformed task identity shows the existing task-changed message without selecting remembered Work; stale revisions and role-ineligible focused reviews remain unavailable. Returning from a task clears its review focus before an ordinary workspace is shown. Valid older `view=develop&record=<id>` workspace links and hosted focus links remain recognized. Navigation does not execute a business command.
