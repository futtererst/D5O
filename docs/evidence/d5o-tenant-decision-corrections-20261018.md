## Connected corrections still required

The next service-Finance correction must update the **same pinned configuration basis** in the typed service Finance decision, invoice review/issue/payment commands, actual-cost correction and their queue projections. `d5o_hosted_service_finance_command_v1` still compares the reviewer to `billing_commercial_lead`; `d5o_hosted_service_invoice_command_v1` does the same for return, review, issue and payment; the service actual-cost command also fixes that role. The Finance panels and action projections mirror those checks. Changing a dropdown or queue label alone would advertise rights that the database denies. An administrator-selected role must be eligible at publication, independent at decision time, and fixed for the applicable Work or service source so a later configuration change does not silently reassign an in-flight decision.

Time-and-materials billing needs a reviewed allocation of actual time and materials to the exact **uncovered** service scope, a retained customer rate/terms basis and a server-calculated invoice amount. `current_service_finance_basis_v1` currently totals all reviewed labor hours for the accepted release, including any covered work; `d5o_hosted_service_billing_terms_command_v1` only accepts `Fixed fee for approved uncovered scope`. The allocation and independent review must be linked to the current release/report revisions and retained customer authorization. Until then the existing fixed-fee path remains the only executable billing basis.

Currency is also an end-to-end source and ledger rule, not a display preference: service invoice/cost rows, purchasing, subcontract, labor and Design cost commands contain USD checks. Any tenant currency change must specify supported currency precision and keep every authority, rate, invoice and cost comparison within one currency without implicit conversion. Graybar is a confirmed Rybex distributor, but the supplier-specific quote/PO and material-cost commands would need stable supplier/account identities before another tenant could choose a different distributor. Governed Work Type additions need versioned contract templates and command compatibility; the hosted prototype preference has correctly been removed, but it is not a substitute for that registry lifecycle.
