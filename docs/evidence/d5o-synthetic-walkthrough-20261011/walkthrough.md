## Reproducible finding and correction

**F-01 — Delivery package cards omit the package name.** On the delivery PM mobile screenshot, two **Prepare package turnover** cards had the same Work title and `Package scope · revision 2`; the package identities were not readable without opening each task. This impairs task selection in a two-package job. `deliveryRoleActions` already computed `packageName`, but the hosted search enrichment could overwrite it with `undefined` when the loaded Work projection lacked the package entry. `FocusedMyWorkBoard` then ignored it and used generic text. The bounded correction preserves the existing projected name and renders it on the card. No command, authority or schema changed. The preserved 61644 preview still runs its older build and continued to show the old text. The separate isolated candidate at 61652 displayed build `62825725851b`; a PM mobile browser showed distinct “South zone controls installation” and “North zone controls installation” cards, with no horizontal overflow. [Final card screenshot](screenshots/delivery/pm-mobile-final-candidate.png). TypeScript, scoped lint and the production-mode build passed.

**U-01 — Dense Define preparation.** The PM's focused `Prepare definition` task showed a broad five-step baseline with eight configured requirements open. The task gives the correct next owner and supporting sections, but completing a new structured definition requires several section changes. This is a synthetic inspection, not evidence that a Rybex user was confused. No redesign was made in this bounded defect fix.

**F-02 — Sign-in loop from workspace chooser.** On the old candidate, a fictional Finance sign-in reached the workspace chooser, but clicking Rybex returned to `/auth/sign-in`. Browser request capture showed a GET to `/auth/sign-out?_rsc=…` before the user clicked “Switch account”: the chooser's Next.js Link prefetched a mutating GET route and cleared the fresh session. The existing account menu had already disabled prefetch; the chooser had not. The bounded fix adds `prefetch={false}` to that chooser link. On final build `62825725851b`, no sign-out prefetch occurred; Finance opened the Rybex workspace. In a same-browser PM → Switch account → Finance test, the page showed Finance identity and four Finance actions, with the PM email absent. This is a reproducible technical fix, not a claim that every auth/browser condition is qualified.
