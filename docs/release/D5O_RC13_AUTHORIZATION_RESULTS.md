# RC13 authorization and replay

Real fictional GoTrue sessions were used against the isolated upgraded historical database. Same-tenant Work and evidence reads succeeded (200). Foreign Work/evidence, wrong Work evidence, wrong-role creation/admin/draft operations and a removed member's existing-session evidence request were denied (403); anonymous reads were denied (401). A forged object-path query could not redirect a valid evidence download. A stale Define draft returned 409. Canonical creation and connected creation returned the original Work on exact replay and 409 `command_reuse_conflict` on conflicting replay. Explicitly disabled published Work Type returned 409. The retained original Work entries and 23 object bytes were unchanged after these controls.

This is **PARTIAL** command security coverage. Suspended-tenant and suspended-membership controls, forged task identifiers, successful independent approvals, privileged command matrix, Scope-change hold, Finance authority and receipt uniqueness for later phase commands remain untested in RC13. A Define submit 409 due an incomplete draft is a business precondition, not a successful authorization denial. Direct Storage 400 responses are not used as proof of per-user RLS decisions.

`storage.objects` RLS remained enabled with no user SELECT policy. Service-only evidence RPC ownership/grants were not changed. No client credential was found in the built static assets.
