Each Work kept its canonical identity from browser creation through accepted Deploy, Operations activation and Finance review. Separate fictional project managers, commercial and delivery reviewers, Design owners/reviewers, scheduling users, field employees, customer acceptance authorities, support recipients, documentation reviewers and Finance users executed their permitted controls. My Work entries were opened and reconciled; resolved Operate and Finance tasks disappeared after the corresponding command. The runner records actor IDs, task IDs and command receipts rather than treating a visible task as authorization.

Tenant A's pinned rules required a Define risk narrative, Design method of procedure, Develop solution evidence, reviewed Deploy evidence and independent Operate documentation review. Each relevant missing prerequisite was rejected before a browser completion path succeeded. Tenant B used its separate optional policy while satisfying the platform's mandatory approval and evidence controls. For both, the phase projection replay matched persisted events; Discover, Define, Design, Develop and Deploy were completed, while Operate remained active with support active. Finance started its distinct review after support activation. No financial completion was invented.

The child connected-service request for each tenant was opened, priced, authorized and converted to exactly one executable job in authenticated browser sessions. This followed the parent Operate handoff in the reused runner. It demonstrates connected-service capability against the same Work, but does not establish that the child-service sequence occurred in the parent Develop time window.
