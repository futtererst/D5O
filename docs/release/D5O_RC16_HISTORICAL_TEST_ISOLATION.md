# RC16 historical test isolation

Environment A was restored from the authorized encrypted 177-entry checkpoint, upgraded to 202 actual entries with the unchanged atomic RC8 pre/215/post bridge, and left without fictional business commands. Environment B was independently restored and upgraded identically, then used only for fictional GoTrue identities, one fictional platform-admin authority fixture following the existing enterprise-admin runner, and bounded authenticated reads/invalid-target requests. Both started network-none. Only B was joined to an internal-only Docker network for local Auth, PostgREST, Storage and Next; no host port was published. The exact candidate application tree was built from a tracked-source-only archive. Its first offline build failed with local ENOMEM at 31 page-data workers; a retry of unchanged source with `CIRCLE_NODE_TOTAL=2` passed.

The application **cannot establish the required fictional tenant boundary in this hosted runtime**. With a genuine fictional session, `/api/d5o-hosted/workspaces` returned 200, but `proxy.ts` returned plain-text 503 for `/api/d5o-platform/provisioning` before its supported `d5o_platform_provision_v1` command could run. The `prototype-design-command` and `purchase-authority` endpoints returned 400 `invalid_target` for a fictional workspace. Their source allowlists contain only `rybex` and `rotork`. Commercial command validation returned 400 `invalid_command` before reaching a workspace decision; that response is not counted as an isolation denial. No fictional tenant, configuration or Work was created. The existing two tenant rows, four prototype-state rows, one spending-position row and 23 Storage metadata objects remained at their original counts.

The 303-table pre-business comparison between A and B found only six known independent-upgrade seed/clock differences plus provider-managed `storage.migrations` changes after local Storage startup. Original Auth identity, prototype-state and spending-position rows matched. This is a **safe stopped rehearsal**, not Gate C acceptance: tenant provisioning, fictional configuration publication, Work creation, spending delegation and initial approval could not run through the candidate without using an original pilot tenant. RC15 proved doing so changes original tenant aggregate/position rows. Do not broaden the hosted proxy or pilot allowlists merely to make the fixture pass.
