# RC4 business contract decision

**Recommended contract: retain two distinct domains. Product-owner acceptance remains DECISION REQUIRED.** This document records a source-supported interpretation; it does not revise the original RC3 requirement by implication.

| Domain | Authoritative boundary | Result |
| --- | --- | --- |
| Delivery-stage field change | `d5o_hosted_field_change_command_v1` requires an **accepted Design release** for the exact package. An assigned worker or authorized delivery actor raises a change; an independent actor assesses it. Scope changes require a priced proposal with cost and schedule impact, independent internal review, exact private customer-authorization evidence, a Design change and a newer accepted release before independent resolution. An unresolved change holds protected field-start, completion, turnover and Work acceptance decisions. | Implemented for delivery after Design acceptance and before Work acceptance. The RC3-C browser run verifies a Deploy correction and completion hold for both tenants; the full scope-change path is not yet end-to-end qualified. |
| Post-handover connected service | `d5o_hosted_operate_command_v1` permits request intake only after parent Support is Active. Coverage, triage, estimate, pinned tenant threshold approval, customer authorization and `d5o_hosted_service_job_command_v1` create one distinct executable child Work with a validated parent/request/asset relationship. Completed parent phases are not rewritten. | Source-supported and browser-qualified for both tenants in the [RC3-C 63/63 result](evidence/D5O_RC3C_TWO_TENANT_BROWSER.json). |

The original RC3 instruction to create the **post-handover service child during parent Develop** is an incorrect acceptance assumption for the current service contract. A delivery-stage scope change is not that child service job. Field changes may be raised in a supported delivery state **after an accepted Design release**; the source does not support an arbitrary Design or early Develop request before that release. If product policy requires a new commercial child job before Design acceptance, that is a separate capability decision, not a test-sequence fix.
