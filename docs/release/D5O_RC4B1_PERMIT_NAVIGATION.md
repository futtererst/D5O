# RC4-B.1 held-permit control disposition

The RC4-B `Authorize resume` control did not dispatch. The [final authenticated capture](evidence/D5O_RC4B1_INTEGRITY.json) reproduces that state for both tenants: the button is **disabled**, and Field readiness says **Hold for resolution**. Its findings identify that the published 08:00–16:59 shift was outside the browser's current UTC time and that material availability was unknown. This is a guarded UI state, not a broken click handler or an HTTP failure.

`DeployWorkspace` uses `assessDeployReadiness` with the real browser time and disables start/resume unless the recommendation is `Ready for authorized start`. It selects a permit only when its `releaseId` matches the current accepted Design release. The disposable database uses a fixed qualification clock for its scheduled-shift command; the browser does not use that test seam. That clock difference explains why the RC4-B resume control was disabled during the captured run. The action is therefore correctly unavailable under the UI's displayed readiness conditions.

After the Scope-driven Design revision, the old Held permit no longer matches the current release. The existing browser path presents **Authorize field start** for the revised release rather than resuming the old permit. Both tenants used that path and received new permits: A `914146ad-0bf4-4ef6-8a25-a20540c51db6` for release `7bc3a628-4bed-4f4d-8aa0-68e727fe435b`; B `b37a11b6-37df-4857-87c3-b416ce2be28b` for release `27c51825-cee8-4eb1-bc69-2b4eaf721999`. The old permit IDs remained Held. Browser field reporting and acceptance then succeeded against the revised basis.

**Disposition: no UI correction.** The disabled control reflects a stated readiness hold; the replacement-permit route is already available and was browser-qualified. Enabling old-permit resume or bypassing the time/readiness assessment would weaken the existing authorization boundary. The separate timestamp-tie defect in the field-fact RPC was fixed by the [forward migration](../../supabase/migrations/20261027190000_d5o_field_fact_latest_permit_order.sql), without changing the browser control.
