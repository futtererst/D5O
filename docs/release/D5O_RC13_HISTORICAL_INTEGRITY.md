# RC13 historical integrity and local recovery

A fresh original 177-entry encrypted checkpoint was restored and upgraded to 202 actual source-ledger entries. A separate original checkpoint was restored for comparison. All original row keys were present except expected full-row digest differences from migration-added columns, synthetic append-only fixture state and provider-managed `storage.migrations` hash updates. Original fields in configuration versions, memberships, crew profiles, workspaces and admin identity requests were not rewritten; new migration columns explain their row-hash differences. The original 15 catalog entries and 18 rybex Work entries were present without nested-entry modification. Existing 25 Auth users/identities remained, with eight fictional users added for tests. All 23 private object hashes matched 2,252,301 retained bytes. No foreign keys were unvalidated.

The raw full-row multiset comparison reports seven differing tables and therefore is **not** a blanket row-hash equality claim. [Original-field classification](evidence/D5O_RC13_HISTORICAL_COLUMN_DELTAS.json), [nested Work preservation](evidence/D5O_RC13_PROJECTION_PRESERVATION.json), [full-row results](evidence/D5O_RC13_HISTORICAL_ROW_DIGESTS.json) and [byte hashes](evidence/D5O_RC13_PRIVATE_VOLUME_INTEGRITY.json) give the precise limits. The separate RC8 post-upgrade checkpoint differs in generated IDs/timestamps and is not used as proof of loss in the original 177-entry state.

The disposable post-upgrade checkpoint restored in **29.37 seconds** (202 ledger); the original checkpoint restored in **29.10 seconds** (177 ledger, 25 Auth users, 23 Storage metadata rows). An injected SQLSTATE `P0001` inside a DDL transaction rolled back the probe table and left the original ledger, Auth and Storage counts intact. These are local timings only. Database and Storage captures were not atomic; coordinated production recovery, production RTO/RPO and post-checkpoint business-event loss window remain unqualified. A future cutover requires write quiescence, drained mutations/uploads, a consistent database/object boundary, verified byte inventory, and separate authorization.
