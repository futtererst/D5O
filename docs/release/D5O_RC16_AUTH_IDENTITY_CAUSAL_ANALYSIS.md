# RC16 Auth identity boundary analysis

**Unresolved historical RC14 difference; no original identity mutation reproduced in RC16.** Two independently restored 177-entry copies received the same reviewed 25-migration upgrade to 202 entries. The original 25 `auth.identities` keys, all columns, and `user_id`/provider relationships matched after each boundary: original restore, upgrade, copy of 82 read-only production Auth provider-ledger identifiers, compatible GoTrue v2.195.0 startup, one fictional signup, sign-in and `/user` lookup, eight total fictional sessions, PostgREST startup, authenticated candidate HTTP reads, invalid-target route probes, and local Storage API startup. The acceptance copy added eight fictional identities, ending at 33; it did not change an original identity row.

The RC14 recorded 25-row reference digest matches the fresh preservation copy. RC14's exercised copy reported 25 missing original full-row signatures, but that disposable database was removed and its evidence contains no per-column diffs. The first RC14 mutation boundary therefore cannot be proven retroactively. A bounded replay of its provider startup, fictional Auth provisioning, and representative authenticated application reads did **not** reproduce it. It would be inaccurate to attribute it to GoTrue or to call it harmless. The precise missing evidence is a retained RC14 post-activity column-level snapshot or a reproducible failing operation. Credentials and original user-to-identity ownership were unchanged in the RC16 replay; no claim is made for the lost RC14 final state.

The original encrypted checkpoint did not capture `auth.schema_migrations` atomically. The 82 provider version identifiers were read from production with a read-only transaction and copied only into the isolated acceptance database for compatible GoTrue startup. This does not prove their value at the checkpoint instant. No production Auth write occurred. [Boundary results](evidence/D5O_RC16_AUTH_ORIGINAL_RESTORE.json) and the subsequent `D5O_RC16_AUTH_*.json` files disclose counts and column names only.
