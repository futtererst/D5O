Every retained encrypted/plain SHA-256 matched, and object metadata ID, bucket, path, and version matched the restored database. The local Supabase Storage API v1.84.19 served all 23 objects to its internal service role over HTTP: 2,252,301 bytes total with identical hashes. The frozen application returned 200 for its tenant-scoped private-evidence index (16 entries for the fictional actor's workspace) and for an authorized download whose hash matched. It returned 403 for an incorrect Work association and another tenant, 401 for anonymous access, and 403 after membership revocation. See [volume restore](evidence/D5O_RC11_PRIVATE_BYTE_RESTORE.json), [Storage API checks](evidence/D5O_RC11_STORAGE_API_CHECK.json), and [application route checks](evidence/D5O_RC11_APP_EVIDENCE_PROBE.json).

The application uses its server-side tenant/Work checks before an internal Storage fetch, which did pass the focused tests. No restored metadata-ID remapping was needed or tested.
