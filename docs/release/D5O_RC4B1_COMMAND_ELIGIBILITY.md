# RC4-B.1 protected-command eligibility

Source baseline: application `96f1b7bccec690c1dec26cf66a55e9526f1619f9`; corrected application and migration commit `8b6b0d9e4aa484d0f0db1d075a969b79e01b0989`; RC4-B evidence `171efdde107bdc7f7fcd8f90da4414832ded4b73`. This matrix describes the effective RPC definitions in `20261027190000_d5o_field_fact_latest_permit_order.sql`, `20261019010000_d5o_configured_delivery_receiver.sql`, `20261020180000_d5o_workforce_field_readiness.sql`, and the `20261009220510_d5o_connected_field_changes.sql` trigger. The API route `prototype-deploy-command` dispatches to these RPCs for connected Work.

| Action | Required basis and actor | Scope guard | Eligibility control |
| --- | --- | --- | --- |
| `save-report` | Current accepted Design, assigned field worker and published booking; factual draft | No completion hold; factual history may be retained | Browser draft save |
| `submit-report` | Same worker, current authorized permit for exact release/publication/schedule, valid draft | No direct Scope trigger on report changes; prior valid work may be reported truthfully | Browser submission |
| `review-report` / `review-inspection` | Independent supervisor / Operations reviewer; submitted report or inspection | No direct unresolved-change hold; evidence and inspection facts remain reviewable | Browser independent review |
| `review-completion` | Operations leader; exact current accepted measured release; reviewed quantity, all verified passing requirements and tenant-required reviewed evidence; no open Deploy issue | `open_field_change_blocks_completion` on the resulting completion write | Controlled disposable checkpoint before a browser-raised commercial change; exact command eligibility must be proved before the change |
| `assemble-turnover` | Project manager or field supervisor; current accepted release and reviewed completion; no open Deploy issue; configured independent receiver | `open_field_change_blocks_completion` on turnover write | Checkpoint after reviewed completion, before turnover |
| `accept-client` | Independent project manager or Operations leader; draft turnover, current reviewed completion and verified requirements; exact private customer PDF for turnover revision | `open_field_change_blocks_completion` on turnover status write | Checkpoint after draft turnover and legitimate evidence upload |
| `respond-operate` | Configured independent Operations receiver; exact client-accepted turnover | `open_field_change_blocks_completion` on turnover receipt write | Checkpoint after customer package acceptance |
| `accept-work` | Project manager or Operations leader independent of package assembly; every current package client accepted; exact private whole-Work PDF; no open Deploy issue | `open_field_change_blocks_completion` on `workAcceptance` write | Checkpoint after client-accepted turnover and legitimate evidence upload |
| `respond-operate-work` | Configured independent Operations receiver; exact pending Work acceptance | Trigger covers Work receipt writes | **Not applicable as a new Scope-open checkpoint**: the field-change command forbids raising a change after Work acceptance (`accepted_work_requires_service_or_amendment`). Existing historical open changes cannot legitimately reach Work acceptance. |

`review-completion` is the authoritative completion decision; there is no separate completion-submission RPC. Inspection verification and worker factual reporting are not classified as Scope-held transitions because the trigger does not cover those state fields. Turnover and acceptance against an obsolete release after Design revision are **not applicable** as current-basis commands; the revised release needs its own execution facts and reviewed completion. All eligibility probes must use valid actors, exact current revisions and evidence, and a disposable checkpoint or rollback that does not consume the protected state.

The final disposable run proved eligibility for `review-completion`, `assemble-turnover`, `accept-client`, `respond-operate`, and `accept-work` for each tenant with the exact command inside a rolled-back authenticated transaction. The same commands then returned `23514 open_field_change_blocks_completion` after a browser-raised, assessed and priced unresolved Scope change; ten probes preserved Deploy state, audit/receipt counts, evidence links, configuration pins and phase projection. See [machine results](evidence/D5O_RC4B1_INTEGRITY.json). Field start and resumption were already causally tested eight times in [RC4-B](D5O_RC4B_EXECUTION_HOLD_MATRIX.md); this run did not duplicate that sweep.
