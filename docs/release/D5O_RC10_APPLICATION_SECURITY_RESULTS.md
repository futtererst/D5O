# RC10 application and security results

On the final ACL-faithful isolated upgrade, **all 112 literal hosted RPC names** found in allowed frozen modules exist. The frozen proxy contract returned 503 for six representative legacy routes in hosted production mode. A rollback-only synthetic authenticated member read its own workspace and published configuration; cross-tenant configuration, private evidence index, and suspended-member configuration calls each failed with SQLSTATE `42501`. RC8's rerun denied cross-tenant and suspended membership with `42501`; a new tenant field-worker invitation failed with `42501`. The synthetic Auth row and membership were rolled back. The two nonempty legacy public table reads returned zero rows under RLS.

The read-only production catalog shows 165 existing public D5O functions: anonymous EXECUTE 0, authenticated 100, service role 48. The final local upgraded database has 199: anonymous EXECUTE 0, authenticated 124, service role 54. All 165 old signatures retained production owner and SECURITY DEFINER identity. One old function gained service-role EXECUTE exactly as frozen migration 234 instructs; no unexpected old-owner or anonymous drift remained. The 34 new functions need a broader behavioral security review before deployment. This does not prove all non-D5O legacy functions are safe.

This is **targeted SQL/RPC and source-route qualification**, not a complete frozen application HTTP run. No real historical credentials were used; no Storage API authorized/anonymous/cross-tenant/revoked download test ran. Dynamic RPC calls, wrong-role and suspended-tenant cases across every command, complete application operations for Design/Develop/Deploy/Scope/Operate/finance, and callable legacy functions outside the `d5o*` inventory remain unqualified. Do not treat the 112-name existence result as those operations passing.
