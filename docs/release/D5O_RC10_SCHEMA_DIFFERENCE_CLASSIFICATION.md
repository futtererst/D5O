# RC10 schema difference classification

The [per-object triage](evidence/D5O_RC10_SCOPE_TRIAGE.json) classifies 72 clean-only public relations and 212 clean-only public policies for the *conditional hosted production surface*. Five relations have frozen source references, all in the gated legacy/proof paths above; the sixth table has none. None of the 72 names occurs literally in restored `d5o_hosted` or public `d5o*` function definitions. Of the 212 policies, 194 target absent relations and 18 target present legacy public relations. In the isolated probe, `authenticated` could read zero rows from two nonempty legacy public tables under RLS; this does not establish policy coverage on every public table.

The 72 relations and 212 policies are **OPTIONAL / INAPPLICABLE for this hosted runtime only**. This is a release-scope finding, not a finding that their historical SQL was executed or that all legacy RPCs are safe. A service-role read would not prove tenant isolation. The 18 policy differences on present legacy tables and the 54 unresolved early/legacy historical object effects remain explicit audit items. RC9's 19 remaps retain their prior text-equivalence finding; RC10 did not alter the 73 historical disposition records or fabricate ledger rows. The static scan cannot detect dynamic SQL, indirect function calls, or future route changes.

The *required active application* objects are the `d5o_hosted` Work/configuration/evidence schema and public `d5o_hosted_*` RPC surface already present after the 25 late migrations. Their complete behavioral transitive closure is **not yet qualified**: 112 literal RPC names were present, but only focused workspace/configuration/auth probes and existing RC8 security probes ran. Any observed missing dynamic dependency, unexpectedly exposed legacy RPC, or incorrect production environment binding immediately changes the classification to **UNRESOLVED** and stops promotion.

The [production ACL inventory](evidence/D5O_RC10_PRODUCTION_FUNCTION_ACL.json) revealed a separate local restore fidelity defect: the first two restored databases over-granted 165 existing public D5O functions. This was an isolated restore artifact, not evidence of production over-grants. A transactionally verified local-only ACL reconciliation recreated the actual production starting grants before the final migration rehearsal. No ACL correction is proposed for production.
