### New external tester onboarding (operator and recipient)

1. **Operator:** Confirm that the recipient explicitly approved invitation and recovery test email, is on the exact server-side recipient list, and has no existing sign-in account. In [Admin → Users & access](https://d5o-system-of-work.vercel.app/work/admin/users?workspace=rybex), choose the intended role, enter a reason and request one invitation. `Provider accepted` means the provider accepted the request; it does not prove inbox receipt. Reconcile an uncertain request in the retained queue before resending.
2. **Recipient:** Open the private hosted invitation email yourself. If another D5O account is signed in, use the page's sign-out action and reopen the same link. Set a password privately, then sign in normally. Never forward the link or password. An expired, reused or invalid link directs you to request a fresh approved email. Before access is granted, the workspace page should say **Account ready · workspace access pending** and show no Work or private evidence.
3. **Operator:** After recipient setup is verified, make a separate reasoned workspace-access decision. For a field worker, use **Admin → Workforce** to create or select a *fictional* roster person, record qualifications and weekly capacity, and bind the confirmed account. That governed binding grants field-worker access; the invitation alone does not. Do not assign another role merely to bypass the binding.
4. **Recipient:** Sign out and sign in again. A bound field worker should land in [My Schedule](https://d5o-system-of-work.vercel.app/work/my-schedule?workspace=rybex), where only their current assignments are visible. An unassigned worker should see a truthful empty state. Use [Forgot password](https://d5o-system-of-work.vercel.app/auth/forgot-password) only with the approved mailbox; recovery must not change access or roster binding.

Record each outcome separately in [the feedback log](./evidence/d5o-synthetic-beta-feedback-20261019.md): provider acceptance, mailbox receipt, link completion, access activation, first-use screen and recovery.
