# GREEN hosted acceptance runbook

Status: executable plan only. No GREEN or production operation is authorized by this document.

Local evidence: [final assessment](../d5o-final-local-qualification/ASSESSMENT.md), [8-case canonical financial result](../d5o-final-local-qualification/evidence/canonical-financial.json), [66-case browser result](../d5o-final-local-qualification/evidence/six-phase-browser.json), and [3-case supported token-expiry result](../d5o-final-local-qualification/evidence/session-expiry.json). Use the exact final commit in the handoff; the tested application/test/evidence tree includes `c12d4ca` and `e03c948`. Resolve whether approved-PO revision is current release scope before declaring local PASS.

1. **Access and custody.** Obtain time-limited GREEN database access through the approved secret manager. Confirm host, project ID, role, SSL mode, and expiry out of band. Do not put connection strings, passwords, service keys, or JWTs in logs or evidence. Verify the operator can read migration history, Auth, and Storage metadata before any write.
2. **Matched recovery point.** Record a synchronized checkpoint for PostgreSQL, GoTrue Auth identities and credentials, Storage metadata and object bytes. Capture counts and hashes for each tenant, critical financial and audit tables, and object manifests. Confirm a provider-supported rollback point and a tested restoration procedure. Preserve the source unchanged.
3. **Exact candidate.** Select the final commit reported in the handoff, verify `git status --porcelain` is empty, and build from that checkout with `npm ci`, `npm run prisma:validate`, `npm run prisma:generate`, `npm run lint`, `npm run typecheck`, and `npm run build`. Record commit, lockfile hash, artifact digest, and effective nonsecret environment bindings. Deploy that artifact only to the protected GREEN candidate after its operator approves the change. Prisma tooling is 7.10.1; the migration ledger remains the Supabase migration authority.
4. **Migration.** Compare GREEN migration ledger, checksums, extensions, RLS, grants, functions, and Storage policies with the candidate. Dry-run pending migrations against a matched restored copy first; then apply only approved pending migrations to GREEN. Verify repeatability and pre/post tenant counts, financial totals, Auth user IDs, object paths, and checksums.
5. **Authenticated acceptance.** Provision two fictional GREEN tenants and separate users for PM, Finance, Operations, administrator, and field roles. Repeat browser Discover → Define → Develop approval → Design release → Deploy → Operate, including rejection/resubmission, My Work, documents, refresh/new sessions, and audit trail. Execute direct API and RPC cross-tenant, wrong-role, stale-revision, and forged-evidence denials; verify no unauthorized rows or objects changed.
6. **Financial boundaries.** For each effective policy version and financial category, test below, exact, and above limits; cumulative commitments and simultaneous approvals, including PO versus subcontract variation competing for one parent cap. Exercise canonical PO draft replacement, approved PO if its revision path is in release scope, subcontract allocation/agreement/variation, labor caps and published reservations, selected delegates, and unauthorized spending. Compare actual authenticated API/UI outcomes to committed rows, totals, and audit events. Denials must have no commitment side effects. The local reference run passed 8/8 plus 20/20 service thresholds; GREEN must reproduce its own results.
7. **Rollback proof.** Trigger a safe disposable failure in GREEN, restore the matched checkpoint into a separate recovery target, and verify Auth identities and sign-in, database relationships and totals, Storage bytes and privacy, and application behavior. Preserve restore logs and timing without secrets. Rehearse returning GREEN to the prior artifact and state.
8. **Promotion decision.** An independent reviewer signs the exact commit, artifact digest, migration ledger, two-tenant acceptance report, financial results, recovery evidence, open defects, and rollback plan. Confirm the legacy service-role JWT exposure disposition through the approved credential process without writing secrets into the report. Production promotion requires separate explicit authorization. Any failed mandatory check, unresolved approved-scope PO revision requirement, or missing matched recovery evidence keeps promotion blocked.
