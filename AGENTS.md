# D5O agent instructions

## Project authority and boundaries

Start with `docs/d5o-repository-guide.md` and current `main` before the older seed/demo README routes. Hosted D5O is the authenticated, persisted `/work?workspace=rybex` application; a seed demo or interface preview cannot establish connected acceptance. Preserve separate release evidence, target-origin and build-identity checks, and explicit production promotion authorization. Do not treat the product-direction package as implementation acceptance.

## Portfolio corrective action (v1)

Apply the [repository-local shared portfolio corrective standard](PORTFOLIO_CORRECTIVE_STANDARD_V1.md), introduced in JARVIS [PR #1](https://github.com/futtererst/jarvis/pull/1), to new corrective work once that standard is published on JARVIS main. This section supplements the project instructions above; the project's own approved requirements and release controls remain authoritative.

For new corrective work, identify this repository, its active branch and HEAD, applicable instructions, approved requirement, and current project state before planning or dispatch. Record the observed failure separately from a suspected or confirmed cause, with evidence and confidence. Check prerequisites, dependencies, and authorization before work starts; suspend only work that depends on a missing external prerequisite. An unknown cause may justify a bounded diagnostic task. Reuse valid evidence and do not retry a blocked task unchanged.

Set an explicit corrective action, expected outcome, bounded scope, and acceptance criteria. Verify the resulting behavior and diff independently; a worker exit code or self-report does not establish completion. A no-change investigation can complete only with a supported finding and evidence. For substantive failures, repeated blockers, security issues, and release problems, record the cause assessment, verification, and a recurrence-prevention lesson in the existing project workflow. Keep routine work brief. Do not bypass this repository's review, data, credential, spending, or release approvals.
